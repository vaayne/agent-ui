# Documentation

Read this for document changes.

- README.md gives generic package use and links to docs/dev. docs/product.md defines scope.
- docs/dev describes current contracts. Update it when behavior changes. Use dated ADRs only when a decision needs a durable record.
- Write public examples with synthetic data. Do not include application routes, private APIs, customer data, or credentials.
- Use precise English with one main action per sentence. Explain causes and limits. Do not copy implementation into prose.
- Add diagrams only when relationships need them. This library has no documentation site or diagram toolchain.
